2026-09-14。历史方案执行状态：**SOURCE_IMPLEMENTED / LOCAL_CHECKS_PASSED / USER_VISUAL_REJECTED**。用户通过“调整”授权执行，当前源码采用候选 A；A/B 对照、功能与短资源检查见 [执行记录](Light流光视觉优化执行记录-v1.9.md)。以下保留目标与验收约束，参数通过不等于视觉通过。

## 1. 目标与适用范围

将 Light 流光调整为清晰、纯净的品牌色细线，配合可感知但轻柔的内侧映射；解决发灰、显脏及线与柔光层次不清的问题。以 Microsoft 的品牌色描边和材质分层思路作为参考，继续使用本项目的 Metal 实现。

本方案规划执行后的顺序是：确认当前问题来自哪些光效层 → 同输入比较两个候选 → 完成功能、视觉和短资源检查 → 提交完整结果供用户视觉确认。没有视觉通过的候选继续记为未通过，不自动修改其他已确认约束。

## 3. 当前发现与待验证判断

**已确认：**v1.8 的 Light 输入饱和度已达上限，且增加了 1.30 倍颜色分量外推。固定样本饱和度增长仍未得到用户视觉认可。因此不能继续以 HSV 上升作为修复完成依据。当前线条额外乘 0.75，柔光映射增益为 1.33，基础材质与流光共用同一画面合成。

**待验证判断：**细线在白底上的覆盖不足，而柔光形成相对更宽的淡色区域，导致视觉重点落在雾状染色上；这是层次和最终对比关系的问题。1.30 倍外推及末端色域裁切也可能影响色彩稳定性，需分层观察，不能直接认定它是全部原因。

执行时用同一生产 shader、相同输入和相位输出四张诊断图：基础、基础加线条、基础加映射、完整合成。另观察合成前后颜色及裁切位置。诊断开关仅放在测试夹具，不增加产品设置，也不将分层图作为最终效果。

## 4. 必须保持的约束

| 约束 | 固定内容 |
| --- | --- |
| Light/Dark 共用几何 | 周期 7 秒、顺时针、尾长占周长 0.20、相同圆角路径、线宽及相位 |
| 共用渐隐和色段 | 头部沿用 Dark 的渐隐范围；尾迹衰减指数 2.0；蓝紫比例仍为 `smoothstep(0,0.9,t)`；柔光扩散范围及包络相同 |
| 线宽 | `max(aa*0.75,0.3)`；本机 2x 高斯尺度 0.375 pt，不为浅底加粗 |
| 品牌色 | 蓝色色相来自 #3B78DD；保留紫色尾部，不改绿、橙等色系；线条和映射读取同一蓝紫色进度 |
| 基础材质 | 流光关闭时，GlassStyle、背景模糊、描边、填色、内光、阴影和像素输出不变 |
| Dark | 保留 v1.8 当前 Dark 输出，固定输入各相位应像素一致 |
| 运动与开关 | 拖动/缩放冻结流光相位，线与映射保持显示；结束后继续且不追帧。映射随流光总开关退出 |
| 产品范围 | 空框体 800×100 物理像素、无系统标题栏、右键关闭；本轮无新增交互、打包或交付 app 更新 |

不得通过降低判定阈值强迫进入 Dark、改变阴影偏移、增加接触色带、增加第二条内线、延长紫段或延长渐隐端点来弥补颜色问题。

## 5. 优化方法

### 5.1 清晰细线与柔光分别控制覆盖

线条保留原有细度，用更充分的颜色覆盖形成清楚的品牌色核心；映射保持相同色相与运动进度，以更轻的覆盖量提供深度。两者仍在同一渲染 pass 中完成，不增加真实绘制层或离屏纹理。

这里调整的是各光效的透明度/颜色细节，几何、色段及运动逻辑完全共用。线条更清楚不等于整体光效更强；若候选形成粗亮边、荧光涂层或映射几乎消失，也应判为失败。

### 5.2 有界颜色与正确透明合成

候选撤销 v1.8 的 1.30 倍超范围颜色外推，使用有界的品牌色派生 RGB，保留混合前预乘范围校正。只调 Light 的颜色及覆盖参数；保留基础玻璃的阴影，继续不加 Light 流光专属中性压暗。

不要在完成线条合成后再做整幅画面增饱和、对比度增强或色相替换。线条与映射先复用同一个适配颜色，分别控制覆盖即可；只有分层证据证明必须分别派生 S/V 时才另记修订，不能默默引入两套色段。

### 5.3 两个限定候选

以下数值均为 Light 完全激活时的端点；中间背景继续使用现有连续适配系数。颜色在 sRGB HSV 中计算，进入 Metal 时正确转为线性 RGB。

| 参数 | 当前 v1.8（对照） | 候选 A：优先 | 候选 B：更深色阶 |
| --- | --- | --- | --- |
| 蓝色色相 | 217.4074° | 相同 | 相同 |
| 蓝色 S | 1.00 | 1.00 | 1.00 |
| V 缩放因子 | 0.92 | 0.92 | 0.88 |
| 蓝头合成前 HEX，约值 | #0058EB | #0058EB | #0054E0 |
| 线条幅度乘数 | 0.75 | 1.00 | 1.00 |
| 映射增益乘数 | 1.33 | 0.90 | 0.90 |
| 颜色分量外推 | 1.30 | 移除 | 移除 |
| Light 额外中性压暗 | 无 | 无 | 无 |

A 先验证“保持颜色、重分配覆盖”的效果；B 仅相对 A 调整色阶，不改变形状、颜色占比或光效范围。B 的 V=0.88 是针对当前发灰问题提出的候选，并非用户已确认降低明度。

线条乘数不等于最终像素不透明度：实际还乘总强度 0.85、沿边渐隐、横截面覆盖及外侧衰减。A/B 理论边界中心的强度上限为 0.85，实际 2x 采样通常更低。不要把这些乘数作为整圈恒定实色边框。

两组都不理想时，提交分层原因和对照，不连续追加一串未记录参数。若仅映射过弱，后续可在相同几何下单独校准覆盖，但不能直接记为已通过。

## 6. 实施工作包

| 阶段 | 工作 | 输出与退出条件 |
| --- | --- | --- |
| P0：建立本轮基准 | 保存当前相关源码/参数及少量固定输入图；生成分层诊断 | 区分线条、映射、基础阴影的作用。v1.8 是比较基准，不是已接受效果 |
| P1：实现有界颜色候选 | 主要修改 BorderFlowShader 的 Light 合成参数；必要时调整 GlassRenderer 的调用；不改时钟/采集控制器 | A/B 均可用原生产 shader 渲染；Dark 与关闭流光输出通过隔离回归 |
| P2：实际视觉对照 | v1.8、A、B 在同一背景、同一相位输出；选技术与视觉上较好的候选完成真实窗口周期检查 | 提供原尺寸、首尾放大和转角样本，记录推荐及其局限；未得到用户视觉确认时不写视觉 PASS |
| P3：功能与短资源复核 | 在最终推荐构建上完成基础检查、功能探针、背景切换和异常路径检查，顺便记录短资源样本 | 所有必测结果明确，失败不以“只改颜色”跳过；测试结束自动清理自建窗口 |
| P4：交付评审结果 | 汇总候选参数、源码运行截图、功能与资源摘要、剩余限制 | 提交完整结果供用户视觉确认；只有用户认可且必测通过才闭合本次视觉优化 |

P2 尚待用户视觉判断时，可以先完成 P3，使最终评审可直接看到完整结果；不为每个工作包额外请求许可。后续用户已通过“调整”授权执行；执行范围及状态见文首记录。

## 7. 验证矩阵

### 图像与背景

固定输入覆盖白底、浅灰底、暖浅底、冷浅底、深色、暗色细节，以及文字/图标/图片混合背景；用实际 Finder 或等效自然背景验证，不只在整面纯白上判断。

A/B 静态对照至少覆盖同一组直边主体、头部渐隐、尾部渐隐和转角相位。推荐候选在白、浅灰、深色下各跑一个完整 7 秒周期；另做一次自然浅色背景和一次明暗切换。窗口截图用于看颜色与实际合成，固定输入图用于可重复定位，二者不能相互替代。

必须同时满足：

- 细线纯净可辨，内侧映射可感知且明显更柔，不出现灰色端帽、脏色雾带、厚描边或完整内圈。
- 首尾沿线完整渐隐；上下截面同时退出，不能上侧空白而内侧仍留下独立线条。转角无毛边、断段或突然变色。
- 蓝紫出现位置与 Dark 的共同进度一致，紫色可辨但不人为延长。不同背景的感知强度允许不同，不能以逐像素颜色相等衡量 Light/Dark 视觉。
- 半高宽和归一化包络保持，不以原始 alpha 通道完全相同作为本轮条件：本次明确调整覆盖强度，alpha 变化是预期行为；不允许借此改变几何或相位。
- 关闭流光后基础输出一致，Dark 固定输入输出一致，基础自适应关闭时流光仍可自行适配。

保存色相、饱和度、亮度、灰阶及横截面结果帮助定位，但不设“饱和度提高 X% 就通过”的替代标准，也不要求自然渐隐的弱端亮度强行单调变暗。

### 功能

使用现有 `scripts/test.sh`、`scripts/check_material_rendering.py`、`scripts/check_source_visuals.py`、`scripts/check_upgrade_smoke.py`，按新候选调整与颜色有关的图像断言，不能删除与本次无冲突的回归。必要时扩展夹具背景，不新建测试框架。

最终候选必须检查：实时背景更新、浅深连续适配、开关恢复、拖动冻结且保持显示、缩放冻结且保持显示、恢复无追帧、隐藏/显示、once 结束、右键关闭，以及注入的权限不可用/Metal 不可用状态。已有 85 秒功能探针覆盖主要状态，但不能冒充 OS 的真实授权操作。

正常交付 app 的真实权限恢复和缺失的其他系统/显示环境仍单独列未验证；本轮不要求再次锁屏，不把旧版本通过记录冒充新路径实测。

## 8. 性能与证据成本

实现约束：复用当前 8×8 统计、现有纹理、采集流、render pass 和动画时钟。候选新增或调整标量颜色计算应尽量复用已有色彩转换；不引入逐帧分配、全屏后处理、额外模糊或噪声纹理。实际性能变化需观察，不宣称零成本。

资源验证复用最终候选的一次 85 秒功能探针，读取其中原有约 7 秒关闭段与 14 秒开启段的 CPU、GPU、FPS、RSS 首末值及峰值；不另跑长时间 RSS 专项，不为每个静态候选重复跑资源测试。该记录用于发现明显异常，不是内存泄漏证明或严格同条件性能排名。

若出现持续增长、明显卡顿、额外采集/模糊频率或资源异常，针对异常做一次短复核并记录环境；不新设 CPU≤13 或 RSS 绝对数字作为无出处的验收门槛。原 U02-06 已知内存问题继续延期，不在本次调色中重开长测。

永久证据仅保留一份参数表、少量原尺寸/局部对照、一张周期接触表和必要 JSON 摘要，目标不超过 2 MB。重复帧留临时目录，不默认录屏或保存全部中间纹理。达到用户可审阅的证据后停止重复采集。
