## 3. 优先实现方案

### 3.1 用一个最终合成阶段绘制边缘

保留现有 CVPixelBuffer → CVMetalTextureCache → 局部 MPS 高斯模糊 → Metal 合成流程。在现有最终 fragment shader 中加入圆角轮廓距离计算后的外扩散、内发光和细边缘项，目标是不新增模糊 pass、不新增中间纹理、不新增独立渲染循环。

- 外扩散：只在玻璃轮廓外计算低强度暗色 alpha，使用有限范围的平滑衰减，在预留区域边界之前降为透明。偏移固定为 0。
- 内发光：只在轮廓以内计算距离衰减；以边界方向与固定光照方向的关系平滑调制强弱和宽度。避免随机噪声、时间驱动光斑、逐帧 CPU 路径构建和不必要的复杂函数。
- 细高光：作为独立窄带，与内发光共享几何计算；移除或停用承载层的临时重复描边，避免两层白边叠加。
- 输出：玻璃内使用实际背景采样，外侧输出预乘 alpha 的暗色扩散，范围外透明。外侧不采样、模糊或不透明重绘桌面；避免把黑色扩散错误写成不透明底色。
- 保持现有 sRGB/线性颜色处理一致，检查深浅背景上的透明边缘；不以普通颜色相加造成过曝。

本方案的效果与成本需实测。如果单阶段方案不能得到目标质量，应先记录差距和备选成本，不自动增加多层离屏模糊或整屏处理。

### 3.2 分离玻璃、窗口与采样坐标

显式维护以下量，禁止继续用 window.frame 代替所有区域：

| 量 | 单位 | 用途 |
| --- | --- | --- |
| requestedGlassSize / actualGlassSize | 显示 px | 外部尺寸合同与实际主体尺寸 |
| glassRectInWindow | pt | 玻璃在透明承载窗中的位置 |
| glassFrameOnScreen | pt | 全局玻璃主体坐标，决定采样与中心锚点 |
| shadowInsets / panelFrame | pt | 光晕留白与窗口总尺寸，参与屏幕限制 |
| sourceRect | 目标显示器 pt | 玻璃主体加原有模糊边距，按显示器裁切 |
| drawableSize | 显示 px | 覆盖主体与透明光晕的最终输出 |

基本关系：`panelSize = glassSize + 两侧透明留白`；按目标 backingScale 换算 drawable，保留玻璃主体中心，靠边时按主规约做最小位置调整。最大窗口宽度仍为 visibleFrame.width−48 pt，高度仍为 visibleFrame.height×0.8；从总尺寸扣除留白后得到最大玻璃尺寸。空间不足时沿用屏幕边界优先规则。

外扩散不扩大背景采样范围。默认 sampleScale=0.5、sigma=12 时，在当前 2x 屏幕、未被屏幕边界裁切的条件下，采样仍应为 **472×122 px**。真正改变 sigma、玻璃尺寸或屏幕缩放时，才重新计算所需采样边距和输出。

在 shader 中由 panel 局部坐标减去 glassRect 原点得到玻璃坐标，再映射到局部采样；光晕留白不能引起背景偏移、拉伸或二次缩放。透明留白不成为新增产品控件；需验证它不吞掉外围鼠标交互，并保留主体拖动和右键关闭。

### 3.3 参数集中管理

计划新增单一 GlassStyle 配置，统一供 renderer、几何计算和开发测试使用。参数分组包括：主体色彩与透明度、圆角、细边、外扩散颜色/强度/范围、内发光颜色/强度/宽度/方向及非均匀程度。

几何长度使用 pt，背景 sigma 继续明确使用采样纹理 px；屏幕尺寸合同使用显示 px。校验有限值、有效区间以及内发光宽度与较短边的关系，避免在默认 50 pt 高度内铺满光带。外扩散范围与预留边距从同一参数推导，避免不同文件分别写死。

**首轮候选，不是已确认设计值**：每侧透明留白可从 6 pt 起做对照，外扩散峰值 alpha 从约 0.10 起调，内发光宽度从约 3 pt 起调。实际衰减必须在边距内完成；若视觉需要更宽扩散，同时报告新增 drawable 面积。最终预设以六类背景截图判断，不能仅凭这些初值定稿。

提供开发配置或显式测试开关，允许外扩散、内发光、细边分别关闭；不增加产品设置面板。

### 3.4 更新与缓存

背景变化、几何变化、材质配置变化分别跟踪版本。相同采样帧和相同配置不提交 GPU 工作；材质参数变化应能触发一次重新合成，不能被当前仅按帧序号去重的逻辑漏掉。

- 颜色、内发光和细边参数变化：复用有效背景与已模糊纹理，只做一次最终合成。
- 外扩散范围变化：更新窗口留白和 drawable，主体采样不应无故变大；几何版本同步后再呈现。
- sigma、玻璃主体位置/尺寸变化：使相关采样和模糊缓存失效，不展示旧几何结果。
- 缓存键包含背景、几何及影响模糊的参数；只保留有限的当前资源，不保留每一版配置的纹理历史。
- 隐藏、会话暂停与休眠时仍停止采集和周期性 GPU 工作。恢复时按最新可见意图重建有效状态，先解决 R05-08。

## 4. 性能约束与成本核算

### 4.1 沿用硬预算

以下摘录自已接受预算，不放宽阈值：

| 指标 | 升级后门槛 |
| --- | --- |
| 默认动态 GPU 帧时间 | P95 ≤12 ms |
| 默认动态呈现 | 每秒计数中位数 27～30 FPS；帧间隔 P95 ≤50 ms |
| 默认动态采样至呈现 | P95 ≤100 ms；最大 ≤250 ms |
| 默认静态 / 动态 CPU | 单核中位数分别 ≤3% / ≤15% |
| 默认驻留内存增量 | 相对同版本无窗口基线，中位数 ≤128 MiB |
| 五分钟内存稳定 | 斜率 ≤1 MiB/分钟，末分钟减首分钟中位数 ≤5 MiB |
| 隐藏 | ≤1 秒停止采集及周期性提交；稳定 CPU ≤无窗口基线+0.5 个百分点 |
| 20 次显示/隐藏 | 隐藏 10 秒后 RSS ≤首次预热隐藏基线+10 MiB；无残留采集流或在途帧 |
| 资源 | queueDepth=3；最多一个 GPU command 在途；应用中间纹理 ≤4；IOSurface 与 drawables 分列统计 |

默认 15 Hz 静态采样上限、30 Hz 动态上限及低电量/热压力降频继续有效；静态无变化时不重复模糊或呈现。材质自身不添加常驻动画、轮询或单独时钟。

最大尺寸逐项报告实际值，按原预算要求验证资源有界、隐藏停止与五分钟稳定；不能把默认尺寸的速度承诺推广为所有尺寸。移动/尺寸变化需验证原预算规定的帧率、延迟和视觉同步，节能降频模式单独报告。

### 4.2 显式计算光晕成本

若玻璃主体为 W×H 显示 px，每侧留白 m pt，backingScale 为 s，则：

`输出面积倍率 = ((W+2ms) × (H+2ms)) / (W×H)`。

以默认 800×100 px、2x、每侧 6 pt 候选留白为例：drawable 为 **824×124 px**，输出像素比原来增加 **27.72%**。BGRA8 单张 drawable 的纯像素数据约从 0.305 MiB 增至 0.390 MiB。这不是实际 GPU 分配或总 RSS；还需计入行对齐、多 drawable 及系统合成资源。

这部分面积增长主要影响最终绘制和合成，不能据此推断 GPU 时间一定增加 27.72%。背景采样和 MPS 模糊面积应保持原口径；通过日志核对，避免外光晕意外扩大最昂贵的背景处理。

首选实现目标为 **附加模糊 pass=0、附加中间纹理=0、静态持续附加提交=0**。这些是待验证的工程目标，不能因硬预算尚有余量而省略新旧成本比较。

### 4.3 测量方式与回归判定

1. 开发阶段先做短时 A/B 诊断，及时定位面积、shader 或缓存开销；不将短测作为五分钟验收。
2. 定稿后冻结同一升级构建。使用同尺寸、同位置、同背景、同电源条件，分别运行关闭新增效果与开启完整效果，并取得该版本无窗口基线。保持透明输出范围一致的开关对照用于隔离 shader 成本；另用旧版/零留白对照评估完整面积成本，两者分开报告。
3. 正式场景预热 30 秒后记录 300 秒，每秒采样 CPU/RSS；记录有效帧 GPU 时间、实际 presentedTime、延迟、资源峰值及分配次数。P95 沿用 nearest-rank，不把未呈现 drawable 或 draw 调用计作有效帧。
4. 默认静态、默认动态、实际最大尺寸及 20 次恢复均验证；加入移动/尺寸过渡和参数切换场景。静态无有效帧时 GPU P95 记为不适用。
5. 分别报告绝对预算判定与新增成本：CPU 百分点差、GPU ms 差、RSS MiB 差、drawable 像素增幅、捕获面积、资源数量和提交次数。微小 GPU 基线不只报告百分比，避免夸大计时噪声。
6. 超过硬预算即失败，不以视觉改善抵消。不超过预算但出现额外常驻纹理、重复静态提交或无必要的采样面积增长，也列为 finding。边界数值或测量受干扰时做针对性复测，不选择性丢弃失败运行。

测试可使用仅绑定测量进程的临时防自动休眠断言；结束释放，产品不持有。桌面锁定、截图失败或背景夹具被覆盖时将场景标为无效，保留原因。默认不重新启用电脑操作指针；需要真实点击/拖动验证时临时使用，结束清理。

CPU/GPU 时间、提交数量是功耗代理，不代表整机瓦数或电池续航。若没有可靠系统能耗读数，结论只写“性能预算与节能调度通过”。

| 尺寸与边缘 | 默认矮框、较大、实际最大、贴边、空间不足 | 主体与 panel 尺寸分别记录；光晕不被裁切；内光带不过宽；玻璃中心与屏幕约束正确 |
| 动态一致性 | 拖动、连续尺寸输入、过渡中断、样式切换 | 无过期采样、跳回旧中心、持续闪烁或布局循环；版本与呈现一致 |
| 生命周期 | 启动中隐藏/恢复、停止中恢复、组合暂停、20 次循环、真实锁屏冷启动 | 最新意图最终收敛；隐藏无持续工作；恢复得到新有效帧 |
| 前景与交互 | 显式前景测试标记、主体拖动、右键关闭、透明留白 | 标记清晰且不进入模糊；关闭有效；留白无新增不可见交互阻挡 |
| 性能与兼容 | 正式静态/动态/最大尺寸；最低系统与真实跨屏 | 预算逐项判定，资源峰值有记录；环境缺失明确标注 |

视觉证据保存实际窗口及其周围背景，必须包含完整外扩散范围；只截玻璃内部无法验证外光晕。默认尺寸在实际显示比例检查，放大图仅辅助看边缘，不以放大图替代正常观看。灰阶/边缘像素比较可辅助判断，不以计算值取代视觉审查。

## 7. 成本超标时的处理

先查重复提交、错误扩大采样、每帧分配和缓存失效；其次精简边缘函数、共享距离计算、在保持视觉要求的情况下缩小有效扩散范围。仍超标时按主规约既定降级顺序执行，降低刷新或采样质量的结果单独报告，并保留必要的浅色边界和厚度线索。

如果达标必须明显削弱外扩散、取消非均匀内发光、改变 800×100 主体合同或提高预算，应记录真实 A/B 与建议，再由用户决定；不自行删除此次两项核心视觉要求。
