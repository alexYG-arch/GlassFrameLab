## 交付与使用

当前应用：[GlassFrameLab.app](../build/GlassFrameLab.app)；便携应用包：[GlassFrameLab.zip](../build/GlassFrameLab.zip)。当前构建为 0syPQS；前一轮 20 秒性能复核为 fcwSCw。旧已验收应用及 ZIP 保留在 `build/pre-adaptive-flow/`；原项目交付 ZIP 未重打包。

默认自适应开启、流光关闭。右键“流光效果”开关，右键“关闭”退出窗口。`--border-flow` 开启循环，`--flow-once` 播放一圈；独立完整配置示例：[border-flow.example.json](../Resources/border-flow.example.json)，通过 `--flow-style FILE.json` 加载。`--no-adaptive-material` 可关闭自适应。已有 `--glass-preview` 路径现在支持 `--flow-phase 0...1` 生成固定相位的原生单帧；没有另建离屏渲染工具链。

## 实现

- 复用已绑定背景纹理，GPU 8×8 共 64 点统计输出到单个 buffer；仅背景序列、采样投影或样式变化时更新，流光不驱动统计或模糊。当前设备报告 buffer allocatedSize 为 16 字节；这不代表功能总内存成本。
- 保留浅色基础端点；背景为大面积深色时连续减弱白色内光/细边。旧样式缺少 strokeColor 时默认白色，基础关闭标志仍生效。
- 独立 BorderFlowStyle/Clock 和着色函数；外沿流光与局部柔光/弥散阴影共用相位，不改写基础材质。首轮基于方案设置；最终精确视觉与生成参考仍存在尺度/风格差别，需要用户看原生截图确认。
- 移动/缩放冻结相位与有效播放时间，保留高光与映射；几何仍正常更新，结束后继续。隐藏暂停，总开关关闭清除；迟到呈现按状态版本丢弃。
- 根据用户补充，外沿亮头保持可辨认的线段，内部映射使用独立的沿边平滑头部包络及向内扩散；修正了先前垂直切口和头部前侧误取紫色尾色。最终 spread=10 pt、innerGlowGain=0.20 是当前实现候选值，未改基础内光参数。

## 最小验证结果

24/24 基础逻辑检查、6/6 生命周期逻辑检查通过；Release 编译、签名和应用 ZIP CRC 检查通过。第一次启动遇到登录界面，5 秒即清理，零有效渲染，不计为通过。

解锁后运行一次约 210 秒短测（q1tXAB），发现光头切口后只修正着色及候选参数，随后用最终 fcwSCw 做直边/转角两张原生单帧及 20 秒局部复核。未再次运行完整 210 秒流程；冻结和恢复结果来自调度代码未改变的前一构建。

|---|---|---|
| 静态、流光关闭 | CPU 中位 0.34755%；预热后零新增提交 | 未重复测 |
| 静止窗口、流光开启 | CPU 中位 4.8683%，30 FPS，GPU P95 1.69392 ms | CPU 中位 6.1119%，30 FPS，GPU P95 0.05792 ms（3～18 秒有效段） |

最初脚本把“开启段模糊/统计总次数必须完全不变”作为条件，因此两个原始检查为 false，保留在 [原始摘要](evidence/ADAPTIVE-FLOW-v13-local-smoke/initial-smoke.json)。该段实际发生了背景变化，不能仅凭总次数增加判断流光重复计算。脚本已改为同尺寸下按背景变化数核对新增次数，最终静态局部复核另行验证了 450 次动画呈现不增加模糊/统计。尚未确定前一段外部背景变化的来源，不将它归因于某个用户操作。

缩放后隐藏/恢复 RSS 从约 70.8 MiB 到约 77.7 MiB，后续约 7 秒持平。短测只记录到这一台阶，未归因为泄漏，也不承诺长期稳定；不重启 U02-06 专项排查。初始化固定增量、跨构建性能差异及长期趋势不由本次短测证明。
