# 背景自适应深色材质升级方案 v1.1

日期：2026-09-14。状态：**planned_not_implemented**。本次调整视觉参考、参数标定顺序与内存验证方案，未实现自适应或静态渲染器。当前只完成代码核对与方案；9mXYWr 已验收构建、应用 ZIP 和原交付 ZIP 不变。用户已明确选择“先制定方案和视觉参数”；本文件不代表新效果已实现或性能已通过。

## 问题与目标

用户希望框体后方为深色、黑色背景时，玻璃的颜色与光效随之调整，避免现有白色/浅色光效突兀。采用框体后方真实背景作为主要输入，不依赖对其他应用“是否开启 Dark Mode”的判断。系统为浅色但背景很暗时仍可显示深色玻璃，系统为深色但背后是白色页面时仍保留浅色背景可辨识性。

现有 ScreenCaptureKit 已捕获框体背后的局部像素，Metal 在真实背景纹理上模糊与合成。透射颜色已经随背景变化；缺口在光效参数：GlassStyle 的 innerColor 固定白色、innerStrength=0.16、strokeOpacity=0.40，fragment shader 也将边缘固定混入白色。白色 tintOpacity 仅 0.008，不能将全部突兀感都归因于填色。

代码依据：[GlassStyle 默认值](../Sources/LabSupport/GlassStyle.swift) 与 [GlassRenderer 合成](../Sources/GlassFrameLab/GlassRenderer.swift)。

本次目标是深背景上减弱白色高光和灰圈，保留透明感、圆角和适度深度；浅色背景保持目前已验收的外扩散分离效果。仅调整框体材质，不增加内部内容、业务 UI、系统主题开关或窗口装饰。

## 本次调整：视觉协调性优先，参数经渲染后确定

按本轮相邻上下文，将用户所说“上一版”记录为 **v0.2**，仅作为视觉协调性参考，不记为精确效果验收通过。[参考图片](previews/adaptive-glass-concept-v0.2.png) 保留其生成来源；图中比例、背景透射位置及光效仍有偏差。v0.3 的刻意压暗未获得更好的整体协调性，不作为继续削弱光效的依据。

保留 v0.2 柔和连贯的轮廓、可感知的内侧厚度与背景融合。深色玻璃可以有适度亮边和局部提亮，不能把“越暗越好”作为优化目标。整体灰雾、背景错位、均匀厚灰圈及偏移阴影不属于应保留的风格。

后续顺序调整为：

3. **端点冻结后接自适应（待执行）**：先保持原 8×8 判定公式为独立候选，用固定端点排除判定系数对材质调色的干扰，再验证整框自适应。不用修改亮度判定阈值来掩盖材质本身的缺陷。
4. **性能与恢复验收（待执行）**：按下述新增内存对照与原预算检查，全部通过后才讨论替换交付；未通过时回退到已验收材质路径。

## 视觉策略

整块框体使用一个自适应系数，不逐像素切换主题，以免形成斑块。对框体主体投影区域统计限制高亮样本贡献后的亮度及深色采样占比；忽略外扩散透明边界、模糊纹理桶的未使用区域及屏幕无关内容。

初版采用连续亮度映射，不设置“刚低于阈值就突然翻转”的二值开关。用亮度过渡区与深色占比共同决定深色材质强度，避免少量黑字或单个暗角触发整框变色。估计器是材质控制信号，不声称精确检测“全部像素为黑色”。

| 项目 | 浅色/混合背景 | 大面积深色背景（候选方向） |
|---|---|---|
| 透射与模糊 | 保留当前背景颜色与模糊强度 | 保留真实暗背景，不铺不透明黑底 |
| 填色 | 维持当前极低强度白色 tint | 过渡到低强度中性暗色 tint |
| 内发光 | 保留非均匀方向与宽度 | 降低强度，白色改为柔和中性灰，避免灰白内圈 |
| 细边 | 保留浅色背景分离效果 | 减弱亮度/不透明度，仍可辨识 |
| 外扩散 | 保留零偏移、淡暗色扩散 | 适度减弱，避免重复加深形成厚边 |
| 圆角/主体尺寸 | 不变 | 不变 |

### 首轮视觉参数 v0.1（保留为标定起点，未冻结）

以下为保留的候选初值，用于独立静态渲染比较；本轮不凭生成图另造一组“已确认”数值。最终采用值以静态标定和用户确认记录为准；不是 Apple 标准，也不是已经得到用户视觉确认的效果。颜色按当前 shader 的**线性 RGB**口径填写，不能直接当作 sRGB 十六进制色值。

| innerColor | [1, 1, 1] | **[0.30, 0.30, 0.30]** | 将内光改为中性灰 |

### 首轮背景判定 v0.1

从主体区域均匀取得 8×8 个线性颜色样本。每个样本亮度 `Y = 0.2126R + 0.7152G + 0.0722B`；同时计算：

- `D`：`Y ≤ 0.10` 的采样比例，代表大面积深背景。
- `L`：`mean(min(Y, 0.20))`，将单个高亮样本的贡献限制在 0.20，避免黑底少量白字独自主导全框。
- 深色系数 `w = (1 - smoothstep(0.025, 0.10, L)) × smoothstep(0.75, 0.95, D)`，范围 0～1。

`w=0` 使用当前浅色端点，`w=1` 使用上表深色端点。纯黑/近黑区域趋于深色端点；白底黑字和明显明暗各半的区域不进入完整深色端点；黑底少量白字可保持主要深色外观。0.10、0.20 等是**线性亮度参数**，不是屏幕亮度百分比或操作系统主题状态。

这组参数属于待验证的工程提案，不作为自动验收标准。它估计背景分布，无法证明全部像素均为黑色；窄亮条、高频图案和边界移动必须用实际截图验证误判。统计端点测试可证明公式行为，不能替代真实材质视觉验收。

亮度必须统一在线性颜色空间计算，不能把 0～255 的 sRGB 数值直接套入线性阈值。上述初始亮度范围需通过黑、近黑、深灰、彩色暗背景与浅色背景的实际截图标定。图案背景和明显明暗各半的背景应保留中间/浅色方案，避免平均值单独主导误判。

## 性能实现建议

1. 复用已绑定到 GPU 的采样/模糊纹理，不新增屏幕捕获、不调用 CPU 全图亮度扫描，不改变现有精确像素去重。
2. 在已有 command buffer 中，合成前增加一次有界的小型 GPU 统计。首选固定 8×8 共 64 个分布采样，计算整框亮度与深色占比；纹理尺寸变大时采样数量不增长。统计直接写入一个很小的 GPU buffer，fragment 合成读取同一结果。
3. 不在每个 fragment 中重复执行整框统计，不将整帧读回 CPU，不增加 CPU 等待 GPU 统计结果的同步点，不增加独立 command buffer 提交。
4. 仅在原本需要渲染的新背景、几何或样式事件中更新。纯静态时不为了“检测主题”轮询、模糊或重绘；隐藏时延续原停采和零在途要求。
5. 初版用空间/亮度连续映射抑制阈值跳变，不新增持续动画定时器。首帧和恢复帧直接使用当前背景的正确材质，避免静态画面停在一半过渡状态。若真实测试仍出现闪烁，再讨论是否引入有明确停止条件的时间过渡，不能预先承诺 200ms 动画却省略其重绘成本。
6. 保持当前应用中间纹理上限与 GPU 在途上限；小型统计 buffer 单列计数，其实际分配不得以有效数据只有几个字节为由忽略。统计核的执行时间包含在原 GPU command buffer 耗时与预算中，不藏出测量口径。

小规模采样仍可能漏掉细小局部亮区，均匀采样也可能与规则图案混叠；需要高对比棋盘、窄亮条和移动亮区检查。对这种不确定场景，优先保持较保守的深色程度，不牺牲边界可见性。

## RSS 与内存增量：预期、限制与验证

**可能增加，当前未实测，不能承诺零增量或具体 MiB。** RSS 是进程当前驻留物理内存的口径，不等于全部分配量，也不等于 GPU 总内存。在 Apple Silicon 上 CPU/GPU 共享物理内存池，但各诊断计数覆盖范围不同，不能直接将 RSS、footprint 与 Metal 分配量相加作为总量。

| 来源 | 预期行为与控制 |
|---|---|
| 两组材质参数与插值 | 只有少量标量/向量；强弱和颜色变化本身不要求新增纹理。保持现有合成 pass，不为浅色/深色各渲染一张图再交叉混合。 |
| GPU 亮度统计 | 64 个样本在计算核内归约，不保存整幅亮度图或采样历史。结果拟用单个 float4（16 字节有效负载）描述亮度、占比、系数和保留位；一次创建、按当前单帧在途规则复用。实际 buffer 分配与对齐可能大于 16 字节，必须报告 allocatedSize。 |
| 新计算管线、shader 与驱动缓存 | 初始化和首次使用可能引入一次性分配/驻留增长；创建一次并复用，不能每帧或每次主题切换重建。具体开销必须实测，不能用 buffer 的 16 字节代替整个功能内存成本。 |
| 中间纹理和采集 | 自适应新增全尺寸中间纹理目标为 0，新增采集流为 0，保持现有模糊纹理复用。若将来发现必须新增，应先解释用途和实际尺寸成本，更新方案再实施。 |
| 诊断与预览 | 不把 PNG、历史帧、亮度日志累积在运行中应用；静态预览进程单独退出，不计入产品稳态样本。诊断沿用低频汇总，不为每次统计写单独文件。 |

RSS 的突然上涨可能来自首次访问页面、管线/驱动初始化或资源分配。一次跳升后持平不能单凭曲线认定泄漏；反复切换、缩放或恢复后持续抬高也不能用“只是缓存”直接解释。需对照资源数量、实际分配量和时间点定位。原 U02-06 的首次像素比较关联仍只是推断，不因本次方案升级获得根因证明。

实施时采用以下对照，避免只看预热后的平稳曲线漏掉启动成本：

- 保留固定旧构建基线；候选分别测禁用自适应、启用自适应。同一候选禁用分支应跳过新增资源初始化，或明确记录仍已分配哪些资源，不能用被共同开销污染的 A/B 推出“零增量”。
- 分别记录启动、首次亮/暗帧、预热 30 秒后 5 分钟稳态的 RSS；如可用同时记录进程 physical footprint、Metal currentAllocatedSize 和新增 buffer allocatedSize。Metal 指标辅助归因，不替代原 RSS 预算，也不能覆盖驱动全部开销。
- 默认尺寸与本机实际最大尺寸分别运行；加入固定尺寸 100 次明暗切换，检查资源分配次数是否随切换增长；沿用 20 次显示/隐藏及隐藏 10 秒回收检查。候选和基线使用一致场景时序，记录冷/热状态与重复测量差异。
- 以恒定数量的 buffer、管线和中间纹理作为结构要求。报告初始化峰值、预热后中位数差、5 分钟斜率、首末分钟差及隐藏回收差值；发现不可解释的新增台阶或持续增长时先定位，不能用固定小采样量作通过理由。
- 继续遵守 [原内存预算](workpacks/WP-00-performance-budget.md)：默认相对同版本无窗口基线 RSS 增量 ≤128 MiB；稳态斜率 ≤1 MiB/分钟且首末分钟中位数差 ≤5 MiB；20 次显示/隐藏后隐藏 10 秒，相对首次预热隐藏基线增量 ≤10 MiB。新增功能的 A/B 差值另列，这些已有预算不是准许它额外占用 128 MiB。
- 暂不擅自设定“新增 RSS 必须 ≤1 MiB”等未经标定的新硬门槛。先完整报告有界固定增量及测量噪声；明显增量需解释和优化，未解释不得自动闭合。新增稳定占用与持续增长分开评估。

[U02-06](本机已知问题.md) 保持原构建、原最大尺寸场景的已知偏差与延期状态。本次验收须识别候选是否仅复现该已知现象；任何新增默认尺寸回归、新增长趋势、不同来源跳升或原偏差加重均不能自动沿用原接受决定。发生回归时回退新增材质路径，正式构建与 ZIP 在新版本验收前保持原状。

## 变更范围与验收

预计产品范围为 GlassStyle、GlassRenderer 及必要的只读诊断字段；只在确有需要时调整控制器。保留 AppKit 主线程边界、最新几何、采样新鲜度及 fallback 恢复规则，不修改 LocalCaptureService 的像素比较来实现材质亮度判断。系统 fallback 在无法取得真实纹理时继续由系统管理，不能用旧自适应状态假装有新背景。

执行时先保留 9mXYWr 作为已验收基线，固定候选后再检查：

- 纯黑、近黑、深灰、暗暖色、暗冷色：没有突出的白圈，材质仍可辨。
- 纯白、浅灰、浅暖色、浅冷色：保持原外扩散及浅背景分离能力。
- 黑底小白字、白底黑字、明暗各半、棋盘、窄亮条：不因局部内容导致整体主题反复跳变。
- 背景明暗变化、连续移动/缩放、一次静态切换后不再变化、隐藏恢复：区域对应正确，无旧主题残留、半过渡停滞或新增常驻重绘。
- 默认和实际最大尺寸的固定构建实测：沿用动态/拖动/缩放 CPU ≤15%、GPU P95 ≤12ms、帧率 27～30、间隔 P95 ≤50ms、延迟 P95 ≤100ms/最大 ≤250ms，以及原内存/资源/隐藏规则。13.5% 仅是工程余量目标，不是新硬门槛。
- 对比当前已验收构建与候选的 CPU/GPU/资源差值，全部增加的统计工作计入。理论上的 64 次采样并不等于已经证明无性能影响。

默认静态仍不得重复提交。最大尺寸 U02-06 的原已知问题保持延期；既有接受决定不自动豁免本次新增的持续增长、默认尺寸回归或 GPU/CPU 超限。新版本的验收结论须明确区分沿用的已知问题与新发现。

测试证据采取有限场景与关键时点截图，新诊断使用一个有界汇总文件，不为每次亮度统计再生成单独 JSON，避免继续放大小文件数量。现有完整日志契约不在本次静默修改。

## 来源与边界

- [Apple — Analyzing memory usage](https://developer.apple.com/documentation/xcode/analyzing-memory-usage)：Metal 的实际资源分配可能大于请求量，需检查资源及实际分配，不以有效负载替代内存成本。
- [Apple — MTLResource.allocatedSize](https://developer.apple.com/documentation/metal/mtlresource/allocatedsize)：用于记录具体资源的分配字节数。以上资料支持测量方法，不证明本方案已经有确定的低内存开销。

- [Apple HIG — Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：材质需要结合背景对比与视觉分离，深背景上的材质可以呈现更深的效果。用于设计方向，不代表本项目已经实现 Apple 私有材质。
- [Apple — MTLCommandEncoder](https://developer.apple.com/documentation/metal/mtlcommandencoder)：计算和渲染命令可编码到 command buffer。用于设计 GPU 内统计到合成的数据流，具体资源依赖仍须按实际编码顺序验证。
- [Apple — Synchronizing CPU and GPU work](https://developer.apple.com/documentation/metal/synchronizing-cpu-and-gpu-work)：CPU/GPU 资源访问与同步影响流水工作。用于避免新增逐帧 CPU 等待；本方案不据此扩大当前在途队列。

已有本机版本仍为带已知问题验收完成；本方案没有覆盖它、替换 ZIP 或启动 UP-03 内存排查。
