## 结果与实现

新增 `StaticGlassRim`，在 macOS 26 的系统玻璃 contentView 内替换原 CALayer.border 描边。内外圆角轮廓共用距离计算，通过两个线性覆盖函数之差生成白边；这是像素覆盖近似，并非对任意曲率的精确面积积分。0.55 pt 线宽、白色 alpha=0.40 保持，直边累计 alpha 实测 112，理论值 112.2。

最终保存一张 68×68 RGBA8 小图，18,496 bytes（约 18.1 KiB）。使用 CALayer.contentsCenter 保持四角原像素，只拉伸颜色不随长度变化的直边段。默认半径下移动、800×100 / 1300×220 / 1600×500 px 尺寸切换复用同一张图；屏幕比例、半径或不能使用小图的紧凑几何变化时更新。新图直接拥有一份 CFData 像素数据，替换图片时禁止隐式过渡。没有新增定时器或常驻 Metal 绘制。

[Apple contentsCenter](https://developer.apple.com/documentation/quartzcore/calayer/contentscenter) 明确规定九区缩放时四角不拉伸、直边只沿长度方向拉伸。这是缓存方式的依据；是否无接缝仍由下面的实际截图验证。

流光关闭和 Metal 不可用时白边仍存在。系统玻璃配方、alpha、通透度、流光颜色/时序、Light 仅柔光行为均没有修改。macOS 13–25 的原 HUD 路径未改变，本次修复未宣称覆盖这些未实测环境。

## 候选取舍与失败保留

1. 像素链核对：原生对照中 screen/window/描边 contentsScale 均为 2，描边没有开启低分辨率栅格化；当前产品框体为 400×50 pt / 800×100 px，窗口位置和尺寸落在整数点。未发现把描边错误设成 1x 的证据。
2. 原实现、CAShapeLayer 原生比例和双倍比例实拍对照：双倍栅格化没有明显消除局部暗接点，因此未采纳论坛中的这个候选。
3. 比较距离 smoothstep、8×8 面积采样参考和内外线性覆盖差。选择后者，保持整体线宽与白色参数。此前将接点暗缺口描述为“明显缓解”过于乐观；用户评审及再次对照确认只有小幅改善，不能认为断点观感已经消除。未观察到明显新增九区拼接缝，但这并不证明原有视觉问题解决，也不能用“正常抗锯齿”替代用户的质量要求。
4. 首个整窗位图实现在缩放时反复分配图像，出现明显资源偏差；减少中间复制后仍不理想。因此没有交付这两个中间版本，改用固定角部小图。
5. 首次流光截图脚本读取到了首帧提交前的状态，误判 flow_visible=false；脚本已改为有期限地等待实际呈现。没有因此修改产品流光逻辑。
6. 最初沙箱内会话查询返回 none/nil，不能判为锁屏；通过桌面访问检查确认已解锁，后续截图均在可用桌面进行。

## 当前构建验证

以下功能结果保留；视觉对照已完成，但结果未被接受。后续应先以局部亮度和覆盖过渡的小样比较验证观感，参数变化必须标明，不能继续仅用绘制方式变化、缓存大小或测试数量证明视觉改善。18.1 KiB 缓存可复用，只有资源路径发生改变或发现新偏差时才复测 RSS。

- Release 构建通过；26/26 LabSupport、6/6 lifecycle 检查通过。
- `StaticGlassRimCheck` 直接编译产品类，验证 20 次移动/重复显示复用图像、三种尺寸复用小图、半径变化重建、中心透明、直边强度不变。该检查不替代视觉验收。
- 当前产品与旧 build 4 实际屏幕合成对照：Light/Dark × 旧版、关闭流光、开启流光、Metal 不可用、大尺寸，共 10 组。正常底材显示、开启时光效可见、故障时底材和白边保留，采集服务初始化次数始终为 0。
- 四个圆角及八处弧线/直线接点已检查；原尺寸判断观感，4 倍最近邻放大定位像素。没有用生成图、调色图或 window-only 截图替代实际合成。
- 最终描边类另在 0 / 0.25 / 0.5 / 0.75 物理像素相位做独立夹具对照。亚像素位置有正常重采样软化，未把这种软化解释为已消除所有抗锯齿差异。产品窗口几何仍遵守原像素约束。
- 14 秒运动路径覆盖程序驱动移动、多个缩放尺寸、隐藏恢复及最终回到 800×100 px。结束时 flow_running=true、flow_visible=true、无桌面阻塞、采集初始化为 0；缩放结束截图白边完整。不是本轮重新完成了真实手工拖动或系统辅助设置验收。
