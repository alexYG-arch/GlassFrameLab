本轮仅源码开发、编译与验证，没有生成 ZIP、签名或更新交付 app。`.build/release/GlassFrameLab` 是开发产物；`build/GlassFrameLab.app` 与 ZIP 不是本轮源码，不能用旧包判断新代码效果。旧 U02-06 保留延期，不宣称完整发布验收或长期无泄漏。

## 根因与责任

- 旧正常 app 启动复现 `permission_required`、零输入帧/零 GPU 提交，显示替代材质且流光停止：[当时状态](evidence/ADAPTIVE-FLOW-v14-source/launch-denied-before-fix.json)。此前直接启动开发二进制有权限，未覆盖正常启动路径；不能把开发运行通过推广为 app 通过。
- 基础 Light 的源码参数没有改动。本轮用升级前冻结着色器与当前实际 Metal 着色器处理同一输入，白、浅灰、明暗混合和彩色背景的默认输出逐像素一致；关闭基础自适应时六种输入均与旧版一致。深色/暗色细节输入在开启自适应后才有差异。排除了这些固定输入下的基础着色器退化，不能据此证明每个实际启动场景无误。此前最新“浅色变弱”反馈没有对应运行状态，不能将其全部归因为权限，也没有通过修改 Light 参数掩盖。
- 流光只有固定冰蓝—青紫高明度配色，缺少浅底适配；细线核心覆盖偏窄，渐隐和抗锯齿进一步减弱浅底显示。固定输入渲染重现了该表现。
- 文档已有 Light 保持要求，但执行未落实旧版同输入对照。流光文档只写“如需适配”，缺少明确浅色要求。把减少 RSS 扩大为减少功能测试，是执行误解并错误放宽文档；现已纠正，不能再用短测替代功能和视觉验收。

## 修改

1. 权限不可用时增加一次说明与右键状态/重连入口；收到权限后利用既有低频 tick 尝试恢复，不新增重试定时器。注入拒绝的自动检查不弹系统权限窗口。Metal 初始化失败也有明确状态与原因入口。移除替代材质背后的不透明底板；这是降级路径修复，不改变基础 Metal Light。
2. 基础 `GlassStyle` 默认参数及 Dark 端点保持。新增独立流光色彩变换：在线性 RGB/sRGB 转换后保持 HSV 色相，只在浅底降低明度、增强饱和度。V 因子 0.64、S 因子 1.12（封顶 1）；是当前候选，不是用户已确认参数。
3. 原 8×8 统计 buffer 的空闲分量记录未截断平均亮度 M；流光使用 `smoothstep(0.12,0.60,M)`，不改基础 Dark 判定。基础自适应关闭而流光开启时，统计仍为流光服务；流光关闭且基础自适应关闭时不做统计。沿用单个 16 字节 buffer、现有背景纹理与 render pass；同一输入的纯动画不重新模糊/统计。
4. 浅底流光核心高斯尺度在当前 2x 下由 0.375 pt 到 0.75 pt，提高边缘覆盖；深底核心不变，基础细边不变。外沿和内部柔光共享同色相适配，仍分别采用短渐隐线头与宽模糊光头，未增加第二条内描边。移动/缩放只冻结相位，不隐藏流光。

Magic UI [Border Beam](https://magicui.design/docs/components/border-beam) 仅作浅底颜色对比的参考；未采用其橙紫默认色值。本项目保留冰蓝—青紫方向。

## 重现入口

- `bash scripts/build_source.sh`：只编译开发二进制和背景夹具，不打包。
- `bash scripts/test.sh`：基础逻辑与生命周期检查。
- `python3 scripts/check_material_rendering.py`：冻结旧着色器与实际当前 Metal 的固定输入对照及色相检查；需要本机 Metal。
- `python3 scripts/check_upgrade_smoke.py`：85 秒源码功能探针；约 21 秒资源样本，非发布验收。
- `python3 scripts/check_source_visuals.py`：源码实时背景矩阵；`python3 scripts/check_source_visuals.py white-flow,gray-flow,finder` 补最终浅色流光和 Finder。
- `./.build/release/GlassFrameLab --border-flow`：查看当前开发版本；默认不带参数时流光关闭，右键可开启/关闭或退出。
