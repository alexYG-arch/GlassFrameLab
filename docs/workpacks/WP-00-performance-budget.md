# WP-00 — 性能预算 v1.1（已接受）

状态：**用户已接受，数值冻结**。2026-09-11 用户确认预算，并纠正默认尺寸为 800×100 显示像素；本修订仅同步单位和窗体范围，数值门槛不变。预算是后续玻璃实现的验收目标，不是当前性能通过证据。

## 基准与测量口径

基准：MacBook Pro / Apple M4 / 24 GB，macOS 26.5.2，内置屏逻辑尺寸 1512×982 pt，display mode/backing 像素尺寸 3024×1964 px，backingScale 2，可用区域 1512×895 pt；接通电源、低电量模式关闭。不使用初次记录的旧 `pixels_wide/high` 字段。

修复后普通 AppKit 校准窗口实测：无窗口驻留内存中位数约 57.50 MiB；静态窗口约 87.73 MiB，增量约 30.23 MiB；动画窗口约 90.78 MiB、单核 CPU 约 6.01%、实际 draw 约 30 次/秒。它只能为宿主开销和工具量级提供参考，不测量 ScreenCaptureKit、Metal 或真实玻璃成本。证据：[本轮 summary.json](../evidence/WP-00-20260911T024830Z/summary.json)。初次及失败运行保留作诊断，不计入本轮通过结果。

正式场景：单个默认 800×100 px（本机 2x 下为 400×50 pt） 玻璃框体、按规约局部采样、默认 sampleScale 0.5。测试分为静态固定图案、持续变化背景、连续移动/尺寸变化、隐藏。GPU 按 command buffer 的 GPU 时间统计；显示帧率使用实际呈现/完成记录，采集 FPS、GPU 完成和呈现 FPS 分开报告。若暂时无法取得呈现时间，则对应指标未验证，不能使用 NSView draw 计数替代。

环境一致时先预热 30 秒，再记录 5 分钟，每秒采样 CPU/内存。P95 使用排序后的 nearest-rank 定义；记录样本数。帧时间仅统计有效帧，无新背景帧的静态时段不能人为补帧。

## 已接受的数值

| 项目 | 验收门槛 | 适用场景与理由 |
|---|---|---|
| 玻璃 GPU 帧时间 | P95 ≤ 12 ms | 有效渲染帧；将原 8～12 ms 表述统一为一个上限，为约 33.3 ms 的动态帧周期保留其他工作余量；尚无实测 GPU 结果 |
| 动态呈现帧率 | 每秒计数的中位数 27～30 FPS，帧间隔 P95 ≤ 50 ms | 持续变化背景、移动与尺寸变化；节能降频后的模式单独报告，不能冒充达到了此默认质量目标 |
| 采样到呈现延迟 | P95 ≤ 100 ms，最大值 ≤ 250 ms | 动态和移动场景；同时审查录屏中是否错位或拖影，数值通过不替代视觉判断 |
| 驻留内存增量 | 预热后中位数比同版本无窗口基线增加 ≤ 128 MiB | 默认单框体；作为尚未实测的首版宿主+管线预算，采集/中间纹理/drawable 另外统计，不将驻留内存解释为 GPU 总内存 |
| 稳态内存增长 | 5 分钟线性拟合斜率 ≤ 1 MiB/分钟，末分钟与首分钟中位数差 ≤ 5 MiB，两项均满足 | 不要求每个采样点单调不增；在预热后判定 |
| 显示/隐藏回收 | 20 次循环后隐藏 10 秒，驻留内存不高于首次预热后隐藏基线 10 MiB；不残留采集流或在途帧 | 允许框架保留少量有界缓存，不要求进程内存完全回到启动值 |
| 静态 CPU | 单核占比中位数 ≤ 3% | 无背景变化的静态玻璃；不持续模糊或渲染重复帧 |
| 动态 CPU | 单核占比中位数 ≤ 15% | 默认框体，给采样与调度保留预算；当前约 6.01% 的 AppKit 校准动画不能证明此目标已达标 |
| 隐藏调度 | 隐藏后 1 秒内结束采集与周期性 GPU 提交；稳定后采集/渲染计数为 0，CPU 中位数不超过无窗口基线 0.5 个百分点 | 清理在途帧不算新周期刷新 |
| 资源数量 | queueDepth=3；应用自建中间纹理 ≤4 张；drawables/采集 IOSurface 分列记录 | 与主规约一致，禁止用中间纹理数替代总资源数 |

大尺寸测试使用本机实际允许的最大框体，逐项报告相同指标；不能把被夹取后的尺寸写成 1600×300 px。以上 GPU/CPU/内存的数值门槛只针对默认单框体；大尺寸仍须满足资源有界、隐藏停止、5 分钟稳态增长门槛，若默认质量达不到 30 FPS 则记录降频及视觉结果，不能宣称全尺寸 30 FPS。

## 功耗判断

当前只具备进程 CPU 和工作次数的代理测量，不宣称精确瓦数。按上述隐藏零工作、静态无重复帧、静态/动态 CPU 上限评估节能行为；若后续环境可提供系统能耗或 GPU 活动指标，使用同背景、同窗口、同电源设置作补充比较。没有这类仪器读数时，报告“节能调度与 CPU 代理验证”，不能报告“整机功耗已降低 X 瓦”。

若预算导致必须显著改变视觉质量，按主规约请求取舍，不自行提高上限。确认本方案不等于确认视觉效果、授予录屏权限或通过最终验收。
