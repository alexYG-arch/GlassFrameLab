# material 系统材质迁移计划 v1.0

日期：2026-09-14；执行更新：2026-09-15。状态：**LOCAL_CHECKS_PASSED_WITH_DEFERRED_TESTS / WAITING_USER_VISUAL**。

用户于 2026-09-15 明确要求执行本计划，M00–M04 已获实施授权。源码默认入口和 main 保持不变；用户后续明确授权独立 Material 打包及推送，包默认 system，原 custom 交付包不变。实施分支为 `material`，独立目录为 `branches/system-material`；计划前提交为 `81ec40b`。已确认的自定义视觉基线固定为 `main` 的 `70ab8ad`（Light 仅柔光 v1.9.3），当前发布的应用 ZIP 不变。

本计划优先于 [v0.1 评估](系统材质分支评估-v0.1.md) 中的建议，保留其成本与差异分析。用户在补测后决定真实“减少动态效果／降低透明度”两项保留未验证、先看视觉。执行结果与未验证项见 [material 实施与验证记录 v1.0](material实施与验证记录-v1.0.md)；文档、自动检查与用户视觉选择分别记录。

## 1. 目标与首版取舍

实现不要求用户开启录屏权限的系统毛玻璃版本，保留已有空框外形、品牌蓝紫光效与运动交互。先验证真实系统底材能否满足视觉要求，再迁移光效，最后完成当前本机的正常应用启动与功能验收。

初版选择 `NSVisualEffectView` / `.behindWindow` / `.hudWindow`。2026-09-15 用户指出交付包在 Finder 浅色背景近乎不透明，实际对比确认 HUD 过度淡化稀疏细节，因此明确调整本机 macOS 26 路线为公开 `NSGlassEffectView` / `.clear`；系统负责背景合成，独立透明层继续负责流光。不使用私有 backdrop/filter API。macOS 13–25 保留 HUD 兼容路径，其视觉不等同于本机 Clear Glass、继续未验证。候选与实测见 [透明度修复 v1.1](material透明度修复-v1.1.md)。

**明暗规则按方案改为跟随视图的 effectiveAppearance（系统或产品外观），不再读取后方像素。** 这属于产品行为变化，不是当前像素适配算法的等价迁移。Light 外观覆盖黑色窗口时，附加光效仍按 Light 规则，仅系统底材自行处理背景。正常产品不新增主题选择菜单；测试夹具可以强制外观，便于验证交叉组合。

这一取舍已按用户的执行指令进入实现；如果仍要求附加流光根据其他应用实际背景亮度切换，应先修订该取舍，不能以隐藏采集恢复原行为。

## 3. 实现结构与边界

### 3.1 后端入口

实现入口为 `--material-backend custom|system`。实施期间默认保持 `custom`，系统测试显式选择 `system`；仅完成本计划不切换交付默认值。2026-09-15 用户另行要求 Material 打包并推送：本次独立 Material 包默认 system；这项授权不延伸为合并 main 或所有未验证项通过。

在创建运行控制器之前解析后端。system 路径直接创建独立系统控制器，不先创建 `RealtimeGlassController` 再制造拒绝权限来进入 fallback。system 与 `--capture-probe`、`--glass-preview` 等采集诊断参数冲突时明确拒绝，不静默采屏。

系统路径不显示“重新连接背景/屏幕录制未授权”菜单。正常产品仍以流光开关和关闭为主；后端信息及采集计数仅写入诊断，不进入普通用户流程。

### 3.2 底材与装饰

原生材质置于框体内部，由系统合成窗后内容；macOS 26 使用 Clear Glass 自有圆角与边缘，不额外叠加 layer 描边；HUD 兼容路径继续使用 behind-window 合成。主体以外保留透明留白。系统视图不接收拖动和右键事件，继续由 `FrameSurface` 承担交互。

先单独验证底材、基础外扩散与边缘，再按差异补充自定义深度装饰。原有 `.hudWindow` fallback 只作为起点，不沿用其“无权限导致降级”的状态和所有视觉参数。禁止在系统材质上方放置不透明填充、截屏快照或另一次背景模糊。

系统底材没有对应当前 sigma 的精确公开调节项。首轮不声称 1:1 还原，也不通过私有属性强行改系统模糊半径。

### 3.3 透明光效层

计划增加独立的 Metal 光效叠加渲染器，输入仅包含框体几何、外观权重、相位和光效参数；不接收背景纹理、屏幕尺寸采集信息或亮度统计 buffer。底材仍由系统合成。

复用 `BorderFlowShader` 的圆角周长、蓝紫进度和柔光包络；将“计算光效”与“把光效混入已采样背景”区分开。旧自定义合成函数保留，避免抽取时改变已确认的 RGB/预乘行为。叠加输出采用与窗口色彩空间一致的预乘透明颜色，流光关闭时全透明或隐藏。

Light 不输出流动细线，只输出原有蓝紫柔光；Dark 输出细线及柔光。参数以 v1.9.3 为起点，但透明叠加的最终颜色由系统底材参与合成，需要单独视觉标定。发现不同颜色观感时先检查色彩空间、透明混合和层级，不默认增加饱和度或扩散范围。

### 3.4 外观与动画状态

外观通过 `effectiveAppearance` 和 `viewDidChangeEffectiveAppearance` 事件更新，不轮询、不读取系统屏幕截图。主题过渡采用一次短渐变，初始规划约 0.2 秒，复用同一渲染调度器；不改变环绕相位，不为外观增加常驻定时器。流光关闭时不运行这段叠加动画。

复用 `BorderFlowClock` 与当前普通状态 30 FPS、低电量/serious 热状态 15 FPS、critical 热状态 10 FPS 的调度策略；将播放条件从“正在采集”改为“窗口可用、光效开启、没有暂停原因”。不要依赖 capture.state 才让系统版动画开始。

状态优先级：关闭/once 已结束 → 隐藏或桌面不可用 → 减少动态效果 → 拖动/缩放冻结 → 正常播放。多个暂停原因应分别保持，不能一次恢复就解除其他暂停条件。

- 拖动/缩放：相位停止累计，图像仍可见，按当前几何重绘；结束后接着运行。
- 隐藏或桌面不可用：停止自身动画与提交；恢复按有效状态继续，不补跑隐藏期间时间。
- once：有效播放一圈后清除附加光效；切换主题不得重启已经结束的一圈。
- “减少动态效果”：首版拟保留静态光效、停止环绕；恢复时继续原相位。首次启用的静态位置需在实际图中确认，不能显示成无效空帧。
- “降低透明度”：遵循系统材质结果，不绕过设置强制透明；正常模式与辅助设置模式分别记录，不把系统有意不透明判作采样故障。
- Metal 不可用：系统底材仍可使用，附加光效不可用；不能转去创建屏幕采集。

## 6. 性能与证据成本

系统模式预期没有采集流、帧队列、背景像素扫描、MPS 背景模糊和亮度统计 buffer；这是架构目标，不是尚未发生的节能实测结论。附加光效复用现有调度，不增加逐帧对象/纹理分配；纹理或 drawable 相关资源只随必要几何变化调整。

只做一组短资源对照：相同尺寸和背景，custom/system 串行，分别复用约 10 秒关闭与 20 秒开启段，优先嵌入功能探针；不对每个候选重复资源专项。不启动长时间 RSS、锁屏循环或录屏收集。异常可针对触发条件短复核一次，仍异常就记录为未解决，不能提高阈值强行通过。

记录应用 CPU、RSS 首末及峰值、实际附加层提交节奏，并观察 WindowServer 与能可靠取得的 GPU 数据。系统模糊成本在合成器，Metal 光效 command 时间不代表总 GPU 成本；WindowServer 又包含其他窗口，短差值仅供判断明显异常。取不到的指标写未测，不填零，不据此声称总功耗下降。

不设无出处的 CPU≤13 或固定 RSS 数值门槛。完成标准是：无多余采集/模糊路径，流光关闭后自身动画停止，开启节奏符合策略，正常操作无可见卡顿或持续异常；性能收益单独说明测量范围。原 U02-06 继续作为 custom 已知问题，不能由 system 的短测宣布解决。

常驻证据目标不超过 2 MB：一份结果摘要、有限背景/转角对照、少量交互关键帧、必要资源样本。重复帧与原始大文件留临时目录，默认无视频。`docs/evidence` 继续被 Git 排除；可读验证摘要写入工作包记录，远端读者无需下载大量帧才能了解完成边界。

## 7. 成本、执行状态与回退

成本仍按熟悉项目的 macOS 工程师估算：M00–M01 约 0.5–1 人日，M02–M03 约 1–2 人日，M04–M05 约 1–2 人日，合计 **2.5–5 人日**（1 人日约 8 小时）。这是一次方向调校的有效工作量估计，不是当前会话耗时承诺；用户等待、多轮主观调整、其他系统/显示器、Liquid Glass 第二路线及发布工程不计入。

当前范围限定已约定的本机 macOS 26 / Apple M4 / 内置 2x 屏。部署目标暂保留 macOS 13，但 macOS 13、外接/跨屏、非 2x 环境继续标为未验证，不扩大验收范围。

执行记录须区分：PLANNED → IMPLEMENTED → LOCAL_CHECKS_PASSED → USER_VISUAL_CONFIRMED。各工作包记录本次提交、实际检查、结果、失败与未验证项；不通过任意阶段都不能写 CLOSED。用户选择采用系统版后，仍只关闭本机已验证范围。

回退优先选 custom 开发入口或退回分支自身的阶段提交，保留用户工作；不修改/强制重置 main。合并、切换交付默认值、正式打包分别按用户明确指令执行。本轮执行包含系统后端代码和验证记录，最终用户视觉选择仍属于 M05。
